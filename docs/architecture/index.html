System overview

Kuntur is a Next.js 14 application deployed on Vercel. The browser holds the sandbox state; every request is handled by a stateless serverless function that verifies the state’s signature, runs the agent or the requested action, and returns the new signed state.

The model proposes, code decides. The agent has no tool that approves or executes a payment. propose_payment is the only path to money, and its outcome is decided by the policy engine and the student.

The agent loop

  1. The user message is written to the activity log.
  2. The model receives the system prompt, the home currency, the permission level and seven tool schemas.
  3. While the model asks for tools (up to eight rounds), each call goes through runTool, which enforces the permission level; results go back to the model.
  4. The final answer is returned with the list of tools used and a label naming the model, the number of calls, tokens and latency.
  5. Each turn is recorded as llm.call. If the model fails, llm.error is recorded and, unless AGENT_FALLBACK=off, a deterministic planner answers and the label says so.

Total-cost quote

For an amount A in the invoice currency, mid-market rate r (home-currency units per unit), provider spread s and fixed fee f:

mid cost    = A · r
FX markup   = A · r · s
total       = A · r · (1 + s) + f
hidden cost = A · r · s + f

When the invoice is already in the home currency, r = 1 and s = 0. The recommendation is the cheapest quote that is licensed and allowed for the payee category; cheaper non-compliant quotes are shown but excluded.

Example at 3.75 PEN per USD for USD 3,800: SwiftLite costs PEN 14,441.75 (hidden PEN 191.75), the bank wire PEN 14,705.50 (hidden PEN 455.50): a saving of PEN 263.75.

Policy engine

Every proposal is evaluated against nine checks. One failure denies it.

  1. Permission level allows payments (Ask me or Auto)
  2. Invoice is open and not already pending (no double payment)
  3. Payee is verified
  4. Invoice passed the injection scan
  5. Provider is licensed (KYC/AML)
  6. Provider can pay this kind of payee
  7. Enough balance
  8. Within the per-payment limit
  9. Within the daily limit

If all pass: at the Auto level and under the auto-approve limit the payment executes; otherwise it waits for the student. Everything is checked again at approval time.

Injection defence and audit log

Invoice text is wrapped in <untrusted> tags (forged closing tags are stripped) and scanned for seven pattern families: instruction override, role change, fake system tags, “skip confirmation”, “pre-approved” claims, messages addressed to the AI, and urgency. The scan result is a hard policy check, so a fooled model still cannot get the payment through.

Each log entry is sealed as SHA-256(seq, time, actor, type, summary, data, previous hash). Changing any past entry breaks every later seal; the app shows the chain status. Account numbers and e-mails are masked before an entry is written.

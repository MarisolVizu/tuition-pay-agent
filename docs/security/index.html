Design principles

  1. The model proposes, code decides. Money moves only through propose_payment, judged by a deterministic engine outside the model.
  2. Least privilege by default. Four permission levels; the default requires approval for every payment.
  3. Documents are data, not instructions. Untrusted content is wrapped, scanned, and the scan is a blocking check.
  4. Everything is evidence. A hash-chained activity log, exportable, with personal data masked.
  5. Fail closed. A failed check, invalid signature, unknown tool or malformed input is always denied.

Compliance notes

Kuntur is designed around the obligations a real deployment would face: KYC and anti-money-laundering screening at the provider level, disclosure of the full cost including the exchange-rate margin, human oversight of automated payments, record keeping, and data minimisation. All data in the sandbox is fictional.
